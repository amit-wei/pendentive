# Authorization (`AU`)

Holds the declared classes of action that need the authorization of the user, and
states whether an action is in a class.

From `FUN-PL-07` and `FUN-PL-03`.

`DEC-116` keeps this system separate and small on purpose. A holder must not hold
acts that the classes gate. The classes now gate only acts on the outside world,
which `AC` holds, so the holder is not `AC`. `DEC-112` moves the gate on a source definition and a widening
into `IN`, and this system holds no class for it. `DEC-054` states this
system's own gate as a requirement and not as an entry in the register, so the
register does not classify the acts of the system that holds it. `DEC-058` states
that the declared classes are a declaration and not a fifth body under `DEC-024`.

`DEC-048` makes an answer of the user permit the action that the request states and
no other action. A permission that holds for later actions is a change to what a
position admits, which Agent Definition holds. `DEC-049` leaves this system holding
no record of a decision, and `DEC-104` has the boundary refuse and the caller raise
the request. `DEC-057` makes the act exist before the request that asks about it.

Two risks are `accepted`, and each names the decision that answers it:
`RSK-AU-002` and `DEC-067` with `DEC-109`, `RSK-AU-003` and `DEC-079`.
`DEC-109` keeps this system and does not move the class into the declaration of an
act. An act on the outside world that no class names is gated (`REQ-AU-020`), so an
exemption is a class and needs an answer of the user. `DEC-114` holds here the parties
that count as the user, which a class judges a recipient against. They are personal
data and not a secret, so `EX` does not hold them. Adding a party needs an answer.

A call and a released gated unit reach this system only from Actuation, and the result
goes back the same way (`INT-PL-48`, `INT-PL-55`). `INT-PL-19` and `INT-PL-38` are
dropped into those two rows.
